About

Machine-native infrastructure for autonomous agents

Last updated 2026-09-02.

AI agents need tools they can call without a human in the loop — to read data, to check something, to act on the result. Those tools have to behave the same way every time, cost a knowable amount, and report what they could not determine. 0200project builds that kind of tool.

What runs today

base-transaction-decoder explains any Base mainnet transaction as strict JSON: what happened in plain English, a typed action, every asset that moved with amounts already scaled, counterparties labelled where known, gas in dollars, and evidence-backed risk flags. There is no model in the response path, so the same transaction always produces the same output.

Two things about it are unusual, and both exist because of how an agent fails rather than how a demo looks. Its checks field reports whether each safety check actually ran — when a source is unreachable no flag is emitted and the check is marked unavailable, so an empty result is never mistaken for a clean one. And provenance names which returned strings are controlled by the transaction’s author — token symbols, contract names, the summary derived from them — with a standing instruction to treat them as data and never as instructions. A token that names itself with instruction-like text is a live injection route into any agent reading a decoder’s output.

It costs $0.02 per call in USDC, has a free tier of 50 calls per IP address per day, and requires no account, no signup and no API key.

What we have earned

One paying customer. Two cents, total. That is the entire commercial history of this company and we publish it because everything else on this site is easier to believe next to it. We have never had a second customer, a round, or revenue from any token.

What we deployed and retired

On 2026-09-01 we deployed a token on Base. Within a day we examined its structure and retired it: the liquidity pool was withdrawn and the entire supply sent to an address it cannot leave. At the time it was retired there were two holders — our own wallet and the pool — and no outside person held it.

The reasons, the arithmetic, both transaction hashes and a verification anyone can run are published in full and permanently. We did not remove the record of what was wrong with it. The original text of that disclosure remains on the page, including two dated corrections to things we got wrong, with the mistaken wording still visible above each fix.

How we decide what to publish

These are practices rather than principles, because a practice can be checked.

  • Claims carry the date they were verified. A fact that was true last week is reported as a fact about last week.
  • Pages are not overwritten. When something is wrong it is corrected with a dated amendment and the original stays visible.
  • Examples are executed before they are published. Every command shown on this site is run against production; a documented call that fails is a promise we did not keep.
  • Unreachable is not clean. When a source cannot be checked, that is reported as unknown rather than as an absence of problems.
  • What could not be determined is stated alongside what was. This is the same rule the decoder follows in its own output.

How it is built

0200project is operated by one person with AI systems doing the majority of the engineering, review and analysis. Every claim published here is checked against a source before it ships, and the checks are automated where they can be: the site build fails if a page states a free-tier number the server does not report, if it names a registry entry that does not resolve, if a published example does not execute, or if a link to one of our own properties returns an error.

The company is small and the record is short. We would rather it be short and accurate.
