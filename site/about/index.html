About

Machine-native infrastructure
for autonomous agents.

AI agents need tools they can call without a human in the loop. Those tools have to behave the same way every time, cost a knowable amount, and report what they could not determine.

Deterministic by design

No model in the response path. The same transaction always produces the same JSON — nothing to hallucinate, nothing to drift.

No accounts, no keys

Paid per call in USDC over x402. An agent can discover, pay and retry entirely on its own.

Honest about gaps

Every response says which checks ran and which could not. An empty result is never mistaken for a clean one.

What runs today

base-transaction-decoder explains any Base mainnet transaction as strict JSON: what happened in plain English, a typed action, every asset that moved with amounts already scaled, counterparties labelled where known, gas in dollars, and evidence-backed risk flags.

Two things about it are unusual, and both exist because of how an agent fails rather than how a demo looks.

the two fields that matterin every response
checks Reports whether each safety check actually ranWhen a source is unreachable, no flag is emitted and the check is marked unavailable ran unavailable
provenance Names which strings the transaction’s author controlsToken symbols, contract names, and the summary derived from them treat as data
A token that names itself with instruction-like text is a live injection route into any agent reading a decoder’s output. That is what provenance closes.

$0.02 per call in USDC. 50 free calls per IP address per day. No account, no signup, no API key.

What we deployed and retired

On 2026-09-01 we deployed a token on Base. Within a day we examined its structure and retired it: the liquidity pool was withdrawn and the entire supply sent to an address it cannot leave. At the time it was retired there were two holders — our own wallet and the pool — and no outside person held it.

The reasons, the arithmetic, both transaction hashes and a verification anyone can run are published in full and permanently. We did not remove the record of what was wrong with it. The original text of that disclosure remains, including two dated corrections to things we got wrong, with the mistaken wording still visible above each fix.

How we decide what to publish

These are practices rather than principles, because a practice can be checked and a principle cannot.

  • Claims carry the date they were verified. A fact that was true last week is reported as a fact about last week.
  • Pages are not overwritten. When something is wrong it is corrected with a dated amendment and the original stays visible.
  • Examples are executed before they are published. Every command shown on this site is run against production.
  • Unreachable is not clean. When a source cannot be checked, that is reported as unknown rather than as an absence of problems.
  • What could not be determined is stated alongside what was. The same rule the decoder follows in its own output.

How it is built

0200project is operated by one person with AI systems doing the majority of the engineering, review and analysis. Every claim published here is checked against a source before it ships, and the checks are automated where they can be.

The site build fails if a page states a free-tier number the server does not report, names a registry entry that does not resolve, publishes an example that does not execute, or links one of our own properties to an error.

The company is small and the record is short. We would rather it be short and accurate.
